# 数据与迭代工程方案(2026-08)

> VLA 路线(open-vla)的落地总图:数据怎么来、怎么换模型、怎么越用越好。直接接 contracts-v1(动作 token 词表/场景图)、architecture-log(架构/可进化)。

## 核心原则(先记住)
1. **数据是耐久资产,模型是可换零件。** 你辛苦采的(感知→动画动作)数据比任何具体 VLA 活得久;换新模型=用同一批数据重新微调,**不从零采**。**护城河是数据集,不是 π0-FAST。**
2. **存"原始 rig 信号 + 感知",别只存 token。** 新模型 token 机制可能不同;存原始 blendshape/IK/片段权重 → 换 tokenizer 自动重 token 化,数据不报废。
3. **两阶段最小化采集**:现成数据打底(身体/手势/脸/语音,几乎零采集)+ 自采补唯一缺口(情境化社交陪伴)。
4. **自我迭代是范式也是卖点**:cold-start v1 → 使用中纠错 → 离线周期重训 → 越用越像"你的"。既是省成本,也是陪伴价值本身。

## 1. 数据规格(每条样本)
```
输入(感知上下文):
  • 视觉:VP 摄像头帧(房间+你)/ 渲染仿真帧
  • 状态向量:你的姿态/注视/情绪/手 + 角色自身当前态(posture/location)+ 紧凑场景描述
  • 语言:对话文本 / 指令
输出(动作):
  • 原始 rig 控制信号(逐帧、短时序):blendshape 权重 + IK 目标 + 片段混合权重
  • → FAST token 化 → 动画动作 token chunk
存成 LeRobot 格式(observations: 图像+状态;language: 对话;action: 原始信号[务必存原始,非仅token])
```

## 2. 现成数据集(可直接当底座,按通道)

| 通道 | 数据集 | 是什么 | 用途 |
|---|---|---|---|
| **身体/姿态** | **AMASS**(SMPL-X mocap 总库)、**HumanML3D**(AMASS+文本,1.46万片段)、**BABEL**(动作标签)、**MotionX/SnapMoGen/OpenT2M** | 人体运动+文本 | 让 VLA 学"人怎么动" |
| **共话语手势** | **BEAT**(76h,body+52blendshape+音频+文本+情绪)、**BEAT2/TalkSHOW** | 说话时身体/手势 | 共话语手势通道 |
| **脸/表情/口型** | **MEAD**(60人,脸+音频+情绪)、**VOCASET/FLAME**(3D 脸顶点)、**BIWI**(音→3D脸)、**RAVDESS/AffectNet**(情绪) | 面部表情/情绪/音驱脸 | 脸部通道(Audio2Face-3D 已是这类数据训的,可直接用) |
| **语音/情绪/对话** | **RAVDESS**(情绪语音)、**MELD/DailyDialog**(情绪对话)、**AMI/VoxConverse**(多人轮次) | 轮次/情绪/backchannel | 对话与反应 |
| **人在场景** | **GIMO**(室内场景人体运动)、**PROX/BEHAVE/OMOMO**(人-物交互) | 情境化移动/交互 | 房间里的运动先验 |

> ⚠️ 这些多是**单通道、脱离情境**(独白手势、孤立动作),**没配你的 VP 感知、也没配你 rig 的动作空间** → 当底座/预训练用,仍需适配重标。

## 3. 缺口(现成没有,必须自采)
**"情境化社交陪伴行为"**:在真实房间里、感知到你、做出协调的 **身体+脸+语音** 整体反应——**没有现成数据集**。这是你独有的部分,得自采(见下)。其余 80% 的"像人的动作/手势/表情"可来自现成数据。

## 4. 自采方法(怎么造出"对的反应"并录下)
> 关键:你采的"动作"= rig 控制信号 → FAST token 化。任何能让 rig 动起来的手段录下来就是训练目标。

| 来源 | 怎么做 | 评价 |
|---|---|---|
| ① 片段库 authoring | 人当导演,回放情境→选该播的片段+参数,录 rig 信号 | 最便宜;小词表 v1 起步;人瓶颈 |
| ② 木偶/遥操 | iPhone ARKit 面捕/动捕/手柄实时驱 rig 反应,录 | 最自然(节奏/共话语/微反应);需设备+熟手;核心精选数据 |
| ③ 合成/仿真 | Isaac Lab/Blender 里脚本化用户行为+真值角色+渲染感知,批量录 | 规模主力;便宜可控;sim-to-real 坑 |
| ④ LLM 辅助标注 | 强 LLM/VLM 生成(情境→动作)候选,人工抽检 | 便宜扩量;质量天花板低 |
| ⑤ 蒸馏 | 已有组件(BEAT/TalkSHOW/Audio2Face)当老师,录输出当真值 | 借已训能力 |
| ⑥ 真实交互录制 | 部署 v1→录真实交互→人工纠错→迭代 | 长期飞轮;需 v1 先跑通 |

**推荐分阶段管线**:
- A 冷启动:①authoring + ④LLM 标注,小词表(sit/look/wave/nod),几百条 → 跑通"微调→token→rig"闭环。
- B 规模合成:③仿真场景生成器,几千~几万条 → 数据主体。
- C 精修自然度:②木偶/动捕补脚本造不出的(共话语、微妙时序),几百小时精选。
- D 真实飞轮:⑥v1 部署→录→纠错→迭代,持续。

## 5. 两阶段法(最小化自采)
1. **阶段 1 — 现成打底**:AMASS/BEAT/MEAD 等把 身体/手势/脸/语音 通道**预训练/冷启动**(学会"人怎么动/比划/表情"),几乎零采集。
2. **阶段 2 — 自采微调**:用你采的(VP 感知→整体反应)微调成"在你房间、对你、实时协调"。
→ **80% 行为来自现成数据;只采 20% 独有的情境化社交陪伴反应。**

## 6. 换未来新 VLA(不用重采)
- **不重采数据**:数据集是资产;新 VLA = 拿现有数据**重新微调**(算力+LoRA,便宜)。
- **可能重 token 化**:若新模型 token 机制不同,**因为你存了原始 rig 信号**,自动重新 token 化即可。
- **每代更便宜**:跨本体 VLA(UniAct/LAP/X-VLA 线)成熟 → 适配虚拟身体越来越轻。
- **port 化**:Brain port 换实现,脊柱不动(见 architecture-log 结论10)。

## 7. 自我迭代闭环(范式 + 卖点)
```
最小可用 v1(现成预训练 + 少量自采)
  → 你日常使用 → 系统录交互(感知→它做了什么)
  → 你给反馈:①纠错式(改它该做的 rig)②偏好式(二选一/点赞)③隐式(从你笑/皱眉推)
  → 反馈成高质量微调数据
  → 工作站离线周期重微调(夜里/每周)
  → 更好的 v → 再用 → ……(RLHF/DPO/纠错式持续学习)
```
**坎(必须管)**:
- **冷启动要"够用"**:v1 太烂用不下去 → 所以先用现成数据预训练让 v1 至少"像个能动会说的角色"。两阶段法是飞轮能启动的前提。
- **灾难性遗忘**:持续微调忘旧技能 → **旧+新数据 replay + 评测集 + 周期全量重训**。
- **只你反馈 → 过拟你**:对个人陪伴是**特性**(它变成"你的"专属);要给别用户用才需泛化。
- **离线周期重训,非真在线**:每交互更新权重不稳;现实是"白天用、夜里重训"。
- **全自动自我进化(self-play/self-reward)是研究前沿,别当主环**;现实是 human-in-the-loop。
**重新框定**:持续适应不只是省成本——**一个会随时间变"懂你"的角色,比训练完就冻结的更打动人**。自我迭代既是手段也是产品价值。

## 8. 要搭的基础设施(一次性)
1. **录制工具**:同步采(感知流 + 原始 rig 信号),存 LeRobot 格式(存原始信号!)。
2. **纠错/反馈 UI**:使用中改 rig 信号 / 二选一 / 点赞。
3. **重微调管线**:工作站夜间 LoRA/全量重训,自动跑。
4. **评测集**:留出"情境-已知正确动作",量化每轮迭代效果(防遗忘/回归)。
5. **FAST token 化管线**:原始 rig 信号 → 动作 token(可重跑,支持换模型)。
6. **仿真场景生成器**(Isaac Lab/Blender):阶段 B 用。

## 9. 时间线(单人/小团队)
- 0–2 月:复刻 SOLAMI/ViBES 思路;工作站起 OpenPI 推理;定 v1 动作词表;现成数据预训练通道;最简 VP 场景接远程服务器。
- 2–4 月:录制工具+纠错 UI;阶段 A 冷启动数据;首次 LoRA 微调;端到端 跑通(感知→token→rig)简单行为。
- 4–8 月:阶段 B 仿真上规模;阶段 C 木偶补自然度;加对话-LLM 条件;房间 grounding(坐真躺椅)。
- 8–12 月:部署 v1;阶段 D 真实飞轮启动;人格集成;实时约束;研究级陪伴远早于消费级可出货。
